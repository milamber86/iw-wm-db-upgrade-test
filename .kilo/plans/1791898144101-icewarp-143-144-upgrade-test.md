# IceWarp 14.3 → 14.4 upgrade test bed on Infralab (EL9)

## Goal

One repeatable, Ansible-orchestrated cycle that (1) provisions a 16 vCPU / 128 GB EL9 VM on
Infralab via the `infralab-hv-orc` control plane, (2) installs IceWarp 14.3.0.12 + a MySQL 8
engine tuned for fast dump import, (3) pulls the latest production `.sql.gz` backups from
`/mnt/data/backup/` over an ephemeral firewall exception, (4) restores them and remaps the
IceWarp databases, (5) validates accounts/services/`iwmon2`, then (6) runs the unattended
14.3 → 14.4 upgrade while capturing per-`ALTER` timings and a benchmark report.

Deliverables: new Ansible roles/playbooks/inventory in this repo, an `ALTER` timing parser,
and a generated benchmark report under `reports/`.

## Data flow

```
control node ──ssh──> 185.138.220.201 (vpsctl API on 127.0.0.1:8765)
      │                     └─ creates iw-wm-upgrade-01 (16vCPU/128GB, 500GB, AlmaLinux9)
      │  discovers leased IP via GET /api/v1/vms/{name}/state → add_host iwtarget
      └──ssh──> iwtarget: OS base → Percona 8.0 (fast-import tuning) → IceWarp 14.3.0.12 → license
prod (vault)  ◄── iptables -s 185.138.220.201 dport22 ACCEPT (add) ── control node
iwtarget ── scp (egress NATs to 185.138.220.201) ──> prod:/mnt/data/backup/bck_db_*.sql.gz
                  │  (control node removes the iptables rule afterwards)
      └─ stop IceWarp → create DBs → gunzip | mysql → remap IceWarp connstrings → start
      └─ tool.sh export account '*@*' → regenerate /opt/iwmon2/config.yml → iwmon2 restart → web check
      └─ enable slow log (long_query_time=0, log_slow_admin_statements=ON, log_output=TABLE)
      └─ run 14.4 install.sh --auto over 14.3 (tee stdout+stderr) → first start runs schema ALTERs

```

## Ordered implementation tasks

1. **Inventory + variables.** Add `inventory/iwupgrade/hosts.yml` with groups `hypervisors`
   (`185.138.220.201`, `ansible_user: root`), `prod` (from vault), `localhost`. In
   `group_vars/all.yml` define: `iw_vm_name: iw-wm-upgrade-01`, `iw_vm_template`,
   `iw_vm_network`, `iw_vm_vcpu: 16`, `iw_vm_memory_mb: 131072`, `iw_vm_disk_gb: 500`,
   `vps_vm_cloud_init` (user + ssh_keys), `iw_distro: RHEL9_x64`,
   `iw_version_143_url`, `iw_version_144_url`, `iw_install_dir: /opt/icewarp`,
   `iw_run_as_user: icewarp`, `iw_nfr_license`, MySQL tuning knobs, prod paths
   (`prod_backup_dir: /mnt/data/backup`, `prod_backup_glob: "bck_db_*_dbiwc*.sql.gz"`),
   `confirm_prod_transfer: false`. Add `vault.yml.example`.

2. **`roles/iw_provision`.** Wrap `ansible.builtin.include_role: name=vps_vm` with
   `vps_vm_state: started`, `vps_vm_wait_timeout: 600`, `vps_vm_idempotency_key`. Then
   `ansible.builtin.uri` `GET {{ vps_vm_api_url }}/api/v1/vms/{{ iw_vm_name }}/state` (Bearer
   `vps_vm_token`), parse `leased_ips | first | default(reserved_ips | first)`, and
   `add_host` `iwtarget` with `ansible_host=<ip>`, `ansible_user=<cloud user>`, plus write
   `inventory/iwupgrade/generated.yml` via `delegate_to: localhost` for re-runs.
   *Note:* `vps_vm` does not expose `machine`; default `pc` is fine (virtio disks/NICs).

3. **`roles/iw_base`.** `dnf` base packages, `/etc/hosts`, timezone, sysctl (reuse
   `iw-test-server/roles/iwsv/tasks/{packages,linux_tuning}.yml` as reference); open IceWarp
   service ports via firewalld (or iptables).

4. **`roles/mysql_fastload`.** Port `iw-test-server/roles/mysql_single` (Percona
   `ps80 release`, `percona-server-server`, `percona-toolkit`, jemalloc) and its `my.cnf.j2`
   with `lower_case_table_names=1`, `innodb_file_per_table=1`, `max_allowed_packet=1G`.
   Add the fast-import drop-in `files/iw_my_fastload.cnf`
   (`innodb_flush_log_at_trx_commit=0`, `sync_binlog=0`, `innodb_doublewrite=OFF`,
   `skip-log-bin`, `innodb_buffer_pool_size=96G` on a 128 GB box) applied for the restore
   window only, then reverted (reference `roles/db_benchmark/tasks/fast_seed_apply.yml` /
   `fast_seed_revert.yml`). Create the IceWarp logical databases + `iwdb` user.

5. **`roles/iw_install`.** Generalize `iw-db-schema-repair/ansible/roles/icewarp_install`:
   `get_url` (with optional `sha256`) → `unarchive` → disable `_install.sh` clean-install
   guards → `install.sh --auto --user icewarp --install-dir /opt/icewarp
   --skip-api-check --skip-ffmpeg-check --start-on-boot 1` with `stdin: /dev/null`; assert
   `tool.sh`; apply `tool.sh set system C_OnlineLicense {{ iw_nfr_license }}`; transcript to
   `/var/log/iw/install-<version>.log`. Parameterize by URL/version so the same role installs
   14.3 (fresh) and later 14.4 (upgrade).

6. **`roles/iw_restore`.** 
   - Verify `confirm_prod_transfer` is true (else fail with instructions).
   - On `prod` (delegate or separate play): resolve the current iptables backend, insert
     `-I INPUT -s 185.138.220.201 -p tcp --dport 22 -m comment --comment iw-upgrade-test -j ACCEPT`,
     record whether it was newly added (reference `iw-cluster-stress-testing` telemetry_firewall
     and `ovb-cloud-migration/.../ip4.sav.j2`), and `iptables-save`.
   - On `iwtarget`: `scp`/`ansible.builtin.fetch`-style pull of the newest `bck_db_*_dbiwc*.sql.gz`
     per component type (`acc/asp/grw/dc/eas/wc`) into `/var/tmp/iwbackup/`.
   - Stop IceWarp (`/opt/icewarp/icewarpd.sh --stop all`).
   - Parse DB name + type from each filename; `CREATE DATABASE IF NOT EXISTS <dbname>`;
     `gunzip -c <file> | mysql <dbname>` under the fast-load drop-in.
   - Remap IceWarp storage to the restored DBs using the sysvar map in
     `iw-db-schema-repair/versions/versions.yml` (`logical_databases`):
     `c_system_storage_accounts_odbcconnstring`, `c_gw_connectionstring`, `c_db_wc`,
     `c_db_eas`/`C_ActiveSync_DB*`, dircache, antispam; for webclient also
     `config/_webmail/server.xml` `dbconn`.
   - **Teardown (always / `block`+`always`)**: remove the prod iptables rule by comment.

7. **`roles/iw_validate`.**
   - `tool.sh export account '*@*'`; assert non-empty and capture to
     `/var/log/iw/accounts.txt`.
   - Regenerate `/opt/iwmon2/config.yml` from `templates/iwmon2_config.yml.j2`. Base it on
     `iw-test-server/roles/monagent/templates/iwmon2_config.j2`; derive `tool.metrics.web.testmail`,
     `globaladmin`, and any monitored-account entries from the exported account list and the
     restored default domain (pick the first admin account if present). Deploy the `iwmon2`
     binary + systemd unit (`roles/monagent/{tasks/deploy_iwmon2,templates/iwmon2_service_file}`)
     and `systemctl restart iwmon2`.
   - Start IceWarp (`icewarpd.sh --restart all`); wait for `iwmon2 tool stat` to report
     `Smtp: 220`, `Imap: 1`, `Xmpp: 1`; run `iwmon2 tool web` and require a `Logout ... OK`.

8. **`roles/iw_upgrade`.**
   - Snapshot pre-state: `tool.sh display system c_version`, DB table counts/sizes.
   - Enable capture on MySQL: `SET GLOBAL log_output='TABLE'; SET GLOBAL long_query_time=0;
     SET GLOBAL log_slow_admin_statements=ON; SET GLOBAL slow_query_log=ON;
     SET GLOBAL log_slow_extra=ON; TRUNCATE mysql.slow_log;` and record `NOW()` as `t0`.
   - Stop IceWarp, then run the 14.4 installer in automatic mode over the existing install,
     capturing **stdout and stderr**: `... 2>&1 | tee /var/log/iw/upgrade-14.4.log`
     (`ansible.builtin.shell`, `set -o pipefail`); `failed_when` on installer rc; keep the log
     on failure.
   - Start IceWarp (`icewarpd.sh --restart all`) so the 14.4 schema migration/ALTERs run; wait
     for services up; record `t1`. Leave slow log on until `t1`, then disable.
   - Verify `tool.sh display system c_version` shows 14.4.

9. **`roles/iw_timing` + `scripts/parse_alter_timings.py`.** Query
   `SELECT start_time, query_time, sql_text FROM mysql.slow_log WHERE sql_text LIKE 'ALTER TABLE%'`
   (optionally `performance_schema.events_statements_history_long` for cross-check). Emit JSON
   (`[{statement, start_time, duration_sec}]`, total, count) and render
   `reports/upgrade_benchmark_<ts>.md` (reuse `templates/report.md.j2` style): per-ALTER table,
   cumulative/total upgrade DDL time, wall-clock install time, and before/after row/table counts.

10. **`playbooks/iw-upgrade-site.yml`.** Plays: (a) `hypervisors` → `iw_provision`;
    (b) `iwtarget` → `iw_base`, `mysql_fastload`, `iw_install`, `iw_validate`; (c) `iwtarget`
    → `iw_restore` (with `delegate_to: prod` firewall tasks); (d) `iwtarget` → `iw_upgrade`,
    `iw_timing`. Add a short `README.md` section documenting the command
    `ansible-playbook -i inventory/iwupgrade playbooks/iw-upgrade-site.yml`.

## Upgrade-timing capture design (why slow log)

The 14.4 schema differences are applied by IceWarp itself (installer + first service start),
so individual `ALTER`s cannot be wrapped by `scripts/timed_sql.py`. MySQL's slow log is the
right instrument: with `long_query_time=0` it records every statement, `log_slow_admin_statements=ON`
includes `ALTER TABLE`, and `log_output=TABLE` gives `mysql.slow_log` rows with microsecond
`query_time` and `sql_text` that persist even for a large migration. `log_slow_extra=ON` adds
detail. `scripts/timed_sql.py` remains available for any manual, measured `ALTER` (e.g. a
re-usable `pt-online-schema-change` comparison on the restored data).

- Upgrade completes unattended; `/var/log/iw/upgrade-14.4.log` present (stdout+stderr);

- `reports/upgrade_benchmark_*.md` + `.json` list every schema `ALTER` with duration.
- Prod iptables exception is removed at the end (verify no `iw-upgrade-test` rule remains).
- Idempotence: re-running `iw-provision.yml` does not create a second VM (idempotency key);
  re-running restore/validate is safe.

## Risks / notes

- **Engine deviation** from the "MariaDB" wording is intentional (confirmed with the user);
  the spec's fast-dump-import tuning is implemented via the Percona drop-in.
- **vpsctl caps**: resolved — Infralab now runs with `max_mem_mb = 131072`, so the 128 GB
  create is within cap (`max_vcpus = 16` also allows 16).
- **cloud-init on the template**: `vps_vm` only injects hostname/user/ssh_keys/password; if
  `tpl_L1_OB_almalinux9.qcow2` is not a cloud-init image the injected user/key may be ignored —
  fallback is a known existing login (root/password) recorded in the inventory.
- **IP discovery**: `vps_vm` does not return the IP; step 2's `GET /vms/{ref}/state` is
  required, and DNS/lease timing can delay the address.
- **`ALTER` capture**: if the upgrade runs `ALTER`s without slow-log admin logging or clears
  the log, fall back to `performance_schema.events_statements_history_long` (bounded history)
  or general log ordering.
- **Prod safety**: transfer is behind `confirm_prod_transfer`; firewall rule is added and
  removed in an `always` block; never leave the rule behind.
- **Restore ordering**: webclient dump is disabled in the current prod backup script
  (`iw-cluster-installer/roles/backups/templates/iwsv_backup.sh.j2`), so `wc` may be absent —
  handle missing component types gracefully.
